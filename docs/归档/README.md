## 规则

1. **这里的文档只读,不再更新。**
2. **不要拿这里的内容当现状依据** —— 里面的进度、路径、阶段编号大多已过时。
3. 需要"现在什么样" → `docs/现状.md`;需要"接下来做什么" → `docs/路线图.md`。
4. 归档不删除,因为有历史价值(踩坑记录、当时的判断依据、决策过程)。

---

## 为什么要有这个目录

2026-08-27 重构前,项目里有**五份互相矛盾的项目总览**,进度分别停在阶段 0 / 3 / 6,
而且**阶段编号有两套**(旧根 README 的「阶段 6」是历史曲线,其他文档的「阶段 6」是工程文件 JSON)。
翻文件的人根本不知道该信哪个。

解决办法不是删掉旧文档,而是**把"活的"和"死的"分开**:
活的集中到 `docs/现状.md` + `docs/路线图.md` + `docs/改善清单.md` 三份权威文档,
死的挪进本目录并在顶部标注 ⚠️。
