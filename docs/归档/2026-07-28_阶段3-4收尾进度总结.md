## 三、3 个 Bug 修复

### Bug 1:重连后永远不读

**根因**:`PollScheduler` `nextPollAtMs_[v] = -1` 永久卡 in-flight。断连瞬间请求在飞,reply 永远不来,`-1` 永远残留;重连后 `onTick` 看到 `next != -1` 条件失败,Variable 永远跳过。

**修法**:`PollScheduler` 加 `resetAll()` 方法,把所有 `nextPollAtMs_` 强制置 0 + 清 `pending_`;`hmi.cpp` 的 `modbus_::connected` lambda 加一行 `pollScheduler_->resetAll()`(重连瞬间就清)。

**改文件**:`PollScheduler.h` / `PollScheduler.cpp` / `hmi.cpp`

### Bug 2:写线圈 0x05 写 0/1(协议不规范)

**协议规范**:`0x0000`(OFF) / `0xFF00`(ON),**不是 0/1**。

**发现**:`WriteScheduler.cpp` 之前写 `quint16(1) : quint16(0)`,依赖 Qt 的 `QModbusDataUnit::Coils` 自动转 — 大部分 Slave 吃,但严格按协议应写 0x0000/0xFF00。

**修法**:`WriteScheduler.cpp` 改 `quint16(0xFF00) : quint16(0x0000)` + 注释。

### Bug 3:"Modbus 错误 / 上一帧未完成(pending=1)" 偶尔弹窗

**根因**:`ModbusMaster` 2026-07-09 加了"并发请求限流"—— 同一时刻只能 1 个未完成请求。`WriteScheduler.cpp:41` 已经有防御 `if (modbus_->pendingCount() > 0) return;`,但 **PollScheduler 没防**,100ms tick 直接发读撞上 WriteScheduler 写未回,被 ModbusMaster 拒 + 弹窗。

**修法**:`PollScheduler.cpp onTick` 顶部加同样防御 + **14 行详细注释**(Wqian 要求"后续写代码写好注释")。

### 踩坑:压力/温度不读了

#1 改完后 **压力/温度不读**(speed 还能读)。Wqian 报"温度和压力不读取 plc 里面的数据了"。

**根因**:`PollScheduler` 读回来的值是 **寄存器原始值**(-32768~32767),**不是**工程值。我配的 `-1000~1000` 把 raw 值拒了。

**修法(A 方案,最小改动)**:
- `Variable::setValue` 签名加 `bool checkRange = true` 默认参数
- 内部 `if (hasRange() && checkRange)` 才查
- `PollScheduler` 调 `setValue(val, false)` — PLC 读路径不查
- `Binding::bindEdit` 仍然默认 true — UI 写路径查
