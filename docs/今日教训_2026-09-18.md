## 1. 工作流教训(2 条新增)

### 1.1 tests CMakeLists 加新 cpp 必须同步(教训 2.2 复用 + 新变种)

**坑**:加 `S7Driver.cpp` 后忘了加进 `HMI_CORE_SOURCES`,**所有 13 个测试** 链接报 LNK2019(`S7Driver::S7Driver(QObject*)` 找不到)。

**教训**:DriverFactory.cpp 引用了 S7Driver 符号 → tests 也得链 S7Driver.cpp(否则 DriverFactory.cpp.obj 引用空)。

**怎么避免**:每次加新 driver / 新 src class,**先 grep 它在哪些 .cpp 引用** → 所有测试的 HMI_CORE_SOURCES 都加。**当日教训文档第 2.2 条已写过,但具体到 driver 模式更明确**:
> DriverFactory + N 个 Driver → tests 必须链所有 N 个 Driver.cpp(否则 DriverFactory.cpp.obj 缺符号)

### 1.2 Ninja generator 缓存陷阱

**坑**:改了 tests/CMakeLists.txt 后,`ninja` 返回 "no work to do" → 但实际链接错误(因为 ninja 用了旧 .obj)。

**教训**:Ninja 不重新跑 CMake configure → 缓存里的 source list 是旧的。改 CMakeLists.txt 后必须:
```bash
cmake -S . -B build -G "Ninja"   # 强制重新 configure
ninja                             # 再 build
```

**怎么避免**:cmake configure 日志必须看"Build files have been written"且有文件改动时间戳。**看到 "no work to do" 时不要信**,先 `touch CMakeLists.txt` 或重新 configure。

## 2. 工具链教训(1 条新增)

### 2.1 Windows + PowerShell 编译必须先 vcvarsall 配环境

**坑**:PowerShell 直接调 `cmake` → 找不到(`cmake.exe` 不在 PATH)。即使把 cmake 加 PATH,**msvc 编译器找不到** `type_traits`(标准库头文件)。

**教训**:Windows + MSVC 编译流程必须是:
```bash
cmd /c '"...\VC\Auxiliary\Build\vcvarsall.bat" x64 >nul && cd /d <project_dir> && cmake --build .'
```

**怎么避免**:所有 Windows 编译命令前置 `vcvarsall` 调用。**PowerShell 不能直接 msvc 编译**(环境变量 INCLUDE/LIB/PATH 都没设)。

## 3. 协作模式教训(1 条新增)

### 3.1 ctest 不通过可能是测试用例过时,不是代码 bug

**坑**:ctest 跑出 `driverFactory_isSupported_modbus` 失败 → `!isSupported("s7")` 返 FALSE。

**实际**:昨日 C.1 写这个用例时 `s7` 还没实现,所以断言 `!isSupported("s7")` 是对的。今日 C.2.3 把 `s7` 加进 isSupported,断言过时了。**不是 S7Driver 实现 bug,是测试断言该更新**。

**教训**:测试失败先看错误信息:
- 断言"某事不该发生"失败 → **业务改进了,断言该更新**
- 断言"某事该发生"失败 → **业务坏了,代码该修**

**怎么避免**:每次 enable 一个新功能 → 搜现有测试用例是否假设"该功能未启用" → 同步更新。

## 5. 教训 5.1:vcxproj QtMoc 必须跟 Q_OBJECT 配对(2026-09-18 追加)

**坑**:C.1 加 `ModbusDriver.h`(有 `Q_OBJECT`)时,vcxproj + filters 只配了 `ClInclude` + `ClCompile`,**漏了 `<QtMoc>`**。CMake/Ninja 路径(用 AUTOMOC)能跑通,所以一直没暴露。**VS vcxproj 路径走 QtMsBuild,看到没有 QtMoc 就不生成 moc_ModbusDriver.cpp → 链接器找不到 4 个符号(staticMetaObject / metaObject / qt_metacast / qt_metacall)**。

**报错形式**:
```
LNK2001: 无法解析的外部符号 "public: static struct QMetaObject const ModbusDriver::staticMetaObject"
LNK2001: 无法解析的外部符号 "public: virtual struct QMetaObject const * ModbusDriver::metaObject(void)const"
LNK2001: 无法解析的外部符号 "public: virtual void * ModbusDriver::qt_metacast(char const *)"
LNK2001: 无法解析的外部符号 "public: virtual int ModbusDriver::qt_metacall(QMetaObject::Call,int,void * *)"
LNK1120: 4 个无法解析的外部命令
```

**教训**:
- Qt 抽象类三件套(教训 1.3/1.4)只是 .h/.cpp 层面
- **vcxproj 层面也要三件套**:`<QtMoc Include>` + `<ClInclude>` + `<ClCompile>`(同一条 ItemGroup)
- AUTOMOC 自动检测不依赖显式声明,但 QtMsBuild 需要 — 两套构建系统规则不一样

**怎么避免**:
- 加新 Q_OBJECT 类 → vcxproj 必须 4 处都配(QtMoc + ClInclude + ClCompile + filters 三者各一对)
- 写一个 `git grep -L 'QtMoc Include' <header>.h` 反查 — 找出所有有 Q_OBJECT 但没注册的 .h
- CI 加 vcxproj build 路径(目前只测 Ninja,vcxproj 漏配不暴露)
