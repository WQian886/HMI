🤖 AI 协作使用指南 · 先读这一节

核心理念：AI 是你的结对编程伙伴 + 私人教练 + 代码审查员，不是"答案机器"。
错误用法："帮我写完这个" → 正确用法："教我完成这个"。
每周学习时间因此从 8-12 小时压缩到 5-8 小时（AI 节省 30-40% 时间），省下来的时间用来做 AI 帮你出的题。

📌 5 种 AI 使用模式

  1. 🎯 出题官—— 让 AI 出 3-5 道题，先做题再看答案。比看书更高效，比看视频更聚焦。
  2. 🧑‍🏫 教练—— 卡住时让 AI 用苏格拉底式提问引导，不直接给答案。
  3. 🔍 审查员—— 把代码贴给 AI，从正确性 / 可读性 / 性能 / 可维护性4 维度打分。
  4. 🎭 模拟器—— 让 AI 扮 OPC UA 服务器 / 面试官 / 用户 / 客户，无成本练习。
  5. 🌉 概念翻译器—— 让 AI 用你熟悉的工业场景类比解释陌生概念（如把"微服务"比作"车间流水线"）。

🚫 红线（不该用 AI 的场景）

  • ❌ 跳过基础练习直接让 AI 写完 —— 练习是为了你会，不是为了"有"
  • ❌ 盲信 AI 输出 —— AI 会编造 API / 编造协议细节（最常错的是版本号和参数），必须查文档
  • ❌ 用 AI 跳过调试 —— 调试是核心能力，AI 帮你找 bug ≠ 你会调试
  • ❌ 用 AI 写关键控制代码（急停 / 安全联锁） —— 必须自己懂每一行

✅ 评估 AI 输出的 3 问

  1. 这段代码我能逐行解释给同事听吗？
  2. 跟官方文档对得上吗？（不放心就查）
  3. 边界情况处理了吗？（空指针 / 超时 / 异常输入 / 资源释放）

Week 2 · OPC UA 概念扫盲

Phase 1 · 协议
主题：把 OPC UA 的核心概念搞懂——节点、属性、订阅、安全
🎯 目标：不写代码，但要能在白板上画出 OPC UA 信息模型。

📚 学习内容

  • OPC UA 信息模型：节点（Node）+ 引用（Reference），万物皆节点
  • 节点类型：Object、Variable、Method、ObjectType、VariableType
  • Variable 节点的属性：Value、DataType、ValueRank、AccessLevel
  • 地址空间（AddressSpace）—— 树形结构，每个节点有 NodeId（如 ns=1;s=Sinusoid）
  • 三种通信模式：Read/Write（请求-响应）、Subscribe（发布-订阅）、Method 调用
  • 安全概念：None / Sign / SignAndEncrypt，证书管理
  • 跟 Modbus 对比：Modbus 是"寄存器地址"思维，OPC UA 是"对象模型"思维

🛠️ 实操任务

  1. 读完 Prosys OPC UA Tutorial Part 1-3：prosysopc.com/blog/opc-ua-tutorial
  2. 打开 Prosopec 官方客户端 UA Expert（免费），连接你的 Prosys Server
  3. 在 UA Expert 里浏览地址空间，找到 Objects/Simulation/Sinusoid 节点
  4. 右键节点 → Monitor → 看 Value 怎么变化
  5. 尝试 Read 节点 → 看返回的 DataType、ValueRank、AccessLevel
  6. 画一张图：把你看到的节点结构画下来（树形），标注每个节点的 NodeId
📦 交付物：1 张手绘或工具画的 OPC UA 地址空间图 + 1 段笔记（200 字总结 OPC UA 跟 Modbus 的 3 个本质区别）。

Week 5 · MQTT 深入

Phase 1 · 协议
主题：把 MQTT 玩明白——主题、QoS、保留消息
🎯 目标：能用 Qt MQTT 模块做一个能发布+订阅的 demo，理解 MQTT 设计哲学。

📚 学习内容

  • MQTT 设计目标：低带宽、不稳定网络、电池供电设备
  • 三大概念：Broker、Topic、Publish/Subscribe
  • Topic 命名规范（工厂场景）：factory/area1/line3/temperature
  • QoS 0/1/2：at most once / at least once / exactly once
  • Retain 消息：最后一个值会被新订阅者立即收到
  • Last Will and Testament（LWT）：设备意外掉线通知

🛠️ 实操任务

  1. 读完 HiveMQ MQTT Essentials Part 1-5：hivemq.com/mqtt-essentials
  2. 命令行练： 
    mosquitto_sub -h localhost -t 'factory/#' -v
mosquitto_pub -h localhost -t 'factory/area1/temp' -m '25.5'
mosquitto_pub -h localhost -t 'factory/area1/temp' -m '26.0' -r
  3. 在你的 Qt 工程里加 Qt6::Mqtt 模块依赖
  4. 写一个 MqttPublisher：每 1 秒发一次模拟温度数据到 factory/area1/temp
  5. 写一个 MqttSubscriber：订阅 factory/#，把收到的消息打到 UI
  6. 测 QoS 0/1/2 行为差异：故意杀掉 publisher，看 subscriber 多久收到 LWT
📦 交付物：1 个 Qt MQTT 收发 demo（订阅界面 + QoS 选择下拉框）+ 1 张 QoS 行为对比笔记。
